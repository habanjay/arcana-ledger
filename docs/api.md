# Arcana Ledger API

This document describes the HTTP surface of `ArcanaLedger.Server` for `ArcanaLedger.Client`: the Aspire starter sample endpoint and the Arcana Ledger business API mounted under `/api/v1`.

## Implementation status

The server exposes:

| Environment | Method | Path | Description |
| --- | --- | --- | --- |
| All | GET | `/api/weatherforecast` | Starter sample endpoint returning five generated weather forecasts. |
| All | \* | `/api/v1/**` | The Arcana Ledger business API described below. |
| Development | GET | `/health` | Readiness health check. |
| Development | GET | `/alive` | Liveness health check. |
| Development | GET | `/openapi/v1.json` | OpenAPI document generated by ASP.NET Core. |
| Development | GET | `/scalar/v1` | Interactive Scalar API reference for the OpenAPI document. |

The business API (`/api/v1`) is implemented with ASP.NET Core Minimal APIs (`Apis/`), JWT bearer authentication (`Services/JwtTokenService.cs`), and a single shared **in-memory mock data store** (`Mocks/MockDataStore.cs`) — there is no database connection, EF Core model, or migrations yet. Service interfaces in `Services/` are independent of the mock implementation so a real persistence layer can replace `Mocks/` without changing endpoint handlers or DTOs. The mock store seeds one demo user (`trader@example.com` / `Str0ngPassword!`, see `Mocks/MockDataStore.cs`) with a sample portfolio, account, instruments, trade, and valuation — **local/demo use only, not production credentials or persistent storage.**

### `GET /api/weatherforecast`

Response `200` is a generated JSON array. The exact values change on each request:

```json
[
  {
    "date": "2026-10-01",
    "temperatureC": 18,
    "summary": "Mild",
    "temperatureF": 64
  }
]
```

The health endpoints are mapped only in Development by the current service-defaults implementation. The OpenAPI document and Scalar reference are also mapped only in Development.

## Business API

The following sections define the Arcana Ledger business API mounted under `/api/v1`, implemented against the in-memory mock store described above.

## Conventions

- **Base path**: all business endpoints are mounted under `/api/v1`, via `ArcanaLedgerEndpoints.MapArcanaLedgerApi` (`Apis/ArcanaLedgerEndpoints.cs`).
- **Format**: JSON request and response bodies, `camelCase` property names, UTF-8.
- **Authentication**: bearer JWT in the `Authorization` header (`Authorization: Bearer <token>`), issued by `POST /api/v1/auth/login`. Endpoints under a user/portfolio scope resolve the owner from the token's `sub` claim; cross-user access returns `403`. `POST /api/v1/auth/register` and `POST /api/v1/auth/login` are the only anonymous endpoints and are rate-limited (`"sensitive"` policy).
- **IDs**: all resource identifiers are `uuid` strings (matches the `uuid` primary keys in the ERD).
- **Money and quantities**: fields backed by `numeric(20, 8)` columns (prices, quantities, cash amounts) are serialized as JSON strings, not floats, to avoid precision loss (e.g. `"entryPrice": "182.50000000"`), via `Dtos/Json/MoneyJsonConverter.cs`. Percentages and rates backed by `numeric` are serialized as numbers.
- **Timestamps**: `timestamptz` columns are serialized as ISO-8601 UTC strings (`"2026-09-29T14:03:00Z"`), via `Dtos/Json/UtcDateTimeOffsetJsonConverter.cs`. `date` columns are serialized as `YYYY-MM-DD`.
- **Pagination**: list endpoints accept `?page=1&pageSize=25` (defaults shown) and return:
  ```json
  {
    "items": [ /* ... */ ],
    "page": 1,
    "pageSize": 25,
    "totalCount": 132
  }
  ```
- **Errors**: failures use the `ApiErrorResponse` envelope (`Dtos/Common/ApiErrorResponse.cs`), a Problem Details-shaped body handled centrally by `ApiExceptionHandler` (`Middleware/ApiExceptionHandler.cs`) for thrown `ApiException`s, and by `UseStatusCodePages` for otherwise-unhandled HTTP status codes (e.g. 401/403/404):
  ```json
  {
    "type": "https://arcanaledger.dev/errors/validation_error",
    "title": "One or more validation errors occurred.",
    "status": 400,
    "code": "validation_error",
    "errors": { "email": ["Email is already registered."] }
  }
  ```
- **Common status codes**: `200` (read/update success), `201` (created, with `Location` header), `204` (deleted/no content), `400` (validation), `401` (missing/invalid token), `403` (authenticated but not the resource owner), `404` (not found), `409` (conflict, e.g. duplicate default portfolio).
